# Release Notes — Agent Eyes v0.10.0

**Target release:** 2026-07-28 after all source, artifact, and hosted-CI gates pass
**Owner:** Jelly Thomas
**Strategy:** Immutable PyPI release through GitHub Trusted Publishing

## TL;DR

Agent Eyes v0.10.0 adds a bounded computer-use transaction fast path. A known
foreground task can now resolve and reuse an existing browser or desktop target,
observe it, perform up to eight locate/action steps, and verify the result in one
`execute` MCP call. Exploratory work uses `observe_target` once and then
`execute`, replacing repeated model-directed tree/search/action loops while
preserving native-first, cross-browser behavior and explicit-only shadow mode.

## What's new

- **`execute` transaction tool.** Combines target resolution, activation,
  observation, in-memory locators, bounded actions, and final verification under
  one monotonic deadline and foreground coordinator lock.
- **`observe_target` discovery tool.** Resolves an exact target and batches up to
  eight selectors into one compact, qualified observation.
- **Event-driven mutation completion.** Native subscriptions are armed before
  dispatch and wake the transaction when the expected state appears; bounded
  adaptive checks remain a watchdog when native events are unavailable.
- **Compact transaction telemetry.** Records only bounded phase durations,
  counts, stable outcomes, and error codes. It does not retain queries, page
  content, typed values, paths, or URLs.
- **Deterministic transaction evidence.** Shared browser-like fixtures, output
  budgets, cancellation/queue stress, resource cleanup checks, and separated
  reference-agent timing are part of the release gates.

## Safety and correctness

- Foreground work never probes or silently falls back to a shadow provider.
- Browser queries inventory supported open browsers before opening a new target.
- Exact target leases are replaced by complete inventories and invalidated on
  uncertainty or mutation.
- Every mutation is dispatched at most once. A cancelled or timed-out unsafe
  action returns `OUTCOME_UNKNOWN`, stops later steps, and must not be retried.
- `consequence="external_write"` explicitly marks submit/send/publish/delete-like
  actions; the compact result never echoes the submitted value.
- Provider references and snapshots are scoped by provider, mode, target,
  generation, and revision, then released on invalidation or shutdown.
- Native hover hit-testing works on macOS, Linux/AT-SPI, and Windows/UI Automation;
  Windows absolute pointer movement accounts for the full virtual desktop.

## Performance contract

- Known task: one MCP call.
- Exploratory task: at most two normal-path MCP calls.
- At most one full observation before the first mutation and one activation.
- Zero fixed orchestration sleeps.
- Compact output limits: `execute` 2 KiB, `observe_target` 4 KiB, catalog 16 KiB.
- Controlled native reference gate: median at most 1 second and p95 at most 3
  seconds over 30 measured runs after three warmups. Model/client time is
  reported separately and is not blended into the Agent Eyes runtime gate.

## Upgrade

For a new or existing installation, one command performs dependency checks,
persistent installation, selected MCP-client configuration, and skill sync:

```bash
uvx agent-eyes@latest setup
```

Then restart only the MCP clients reported as changed and verify:

```bash
agent-eyes --version
agent-eyes doctor --verbose
```

Do not run separate `install` and `init` commands after a successful `setup`.
Those remain repair/advanced flows.

## Compatibility and known limits

- The legacy tools remain available; `execute` and `observe_target` are additive.
- Foreground native accessibility remains the universal provider. Browser bridges
  are optional accelerators, not required dependencies.
- Linux/Wayland physical input depends on compositor/session support.
- Accessibility can expose only the structure a browser or app publishes to its
  assistive-technology provider.
- Live Bitbucket write benchmarking is intentionally opt-in and must use an
  explicitly authorized disposable pull request.

## Rollback

PyPI artifacts are immutable. If rollback is required, yank 0.10.0, install
`agent-eyes==0.9.0`, rerun setup for the selected clients, restart those clients,
and publish a corrective patch version. No data or database migration is involved.
